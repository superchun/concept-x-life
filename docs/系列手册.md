# 《人生 bug 图鉴》系列手册

做新一期时照这份手册走：先填第 3 节的选题表，再按第 4 节的时间模板排分镜，画面和文案的做法分别在第 5、6 节，代码怎么复用在第 9 节。第一期（BUG-001 局部最优）是所有模板的填写范例。

## 1. 系列公式

**一个概念的机制，解释一种人人都有的困境，用一个能跑的像素世界演出来。**

每期由四样东西组成，缺一样就不成立：

| 组成 | 说明 | 第一期 |
|---|---|---|
| 困境 | 观众已经在经历、但说不清原因的事 | 明明不满意，却一直不动 |
| 概念 | 计算机或数学里的一个机制，结构和困境相同 | 局部最优 |
| 世界 | 把机制做成一个像素小游戏，主角就是「你」 | 小人爬山，只能往上走 |
| 补丁 | 这个机制在学科里已有的解法，翻译成一句人话 | 模拟退火：偶尔允许走一步下坡 |

固定的形式：16:9 横屏，无人声，屏幕文字加音乐，全像素游戏风，100 秒左右。

## 2. 概念怎么选

一个概念要同时过这五关：

1. **机制反直觉。** 能写成「因为 A，所以反而 B」的悖论。（每一步都选更好，所以被困住。）
2. **和困境同构。** 困境里的每个要素在概念里都有对应物，不是比喻沾边。（山顶 = 现状，下坡 = 变差，更高的山 = 更好的可能。）
3. **能做成世界。** 可以画成小人在规则下行动的画面，并且规则能写成一块牌子。
4. **有补丁。** 学科里有一个有名字、有出处的解法，改的是规则本身，不是「要努力」。
5. **能跑出数字。** 写一个小仿真，改规则前后有明显对比。（100 人里 27 人到顶，变成 94 人。）

第 2 关最容易自欺。检验办法：把日常例子逐条对到机制的结构上，对不上的例子说明概念选错了或例子选错了。

## 3. 选题表

开工前填完这张表。填不出来的格子就是还没想清楚的地方，不要开始做画面。

| 项 | 要求 | 第一期 |
|---|---|---|
| 编号和名字 | BUG-00X + 概念名 | BUG-001 局部最优 |
| 困境 | 一句话，不带术语 | 不满意，却一直不动 |
| 悖论（开头两句） | 第二句推翻第一句 | 这十年，你每一步都选了更好的。/ 所以，你被困住了。 |
| 机制的结构 | 列出 3 条成立条件 | 现状是一步步选出来的，不差；往旁边动一下会先变差；知道有更好的可能 |
| 共同动作 | 六个症状共有的一个动作 | 试了新的，不如原来的，又退回去 |
| 六个症状 | 见第 6.2 节 | 奶茶、理发、游戏、学习、工作、和 TA |
| 世界 | 地图、主角、规则牌上的字 | 六座山；小人；「只能往上走」 |
| 代价 | 主角尝试改变时失去什么，三个词 | 分数、效率、体面 |
| 补丁 | 名字、出处年份、一句人话 | 模拟退火，1983 年，「偶尔，允许自己走一步下坡」 |
| 状态变量 | 一个随剧情变化、能用天色表现的量 | 温度 |
| 仿真数字 | 改规则前 → 后，以及没成功的 | 27 → 94，还有 6 个没到 |
| 金句一（诊断） | 否定观众的自责 | 困住你的不是懒，是你太会选「更好」。 |
| 金句二（结论） | 全片要被截图的那句 | 只肯往上走的人，到不了最高的地方。 |
| 结尾动作 | 能从金句二直接推出来 | 下一步，不必更好。 |
| 最后一问 | 一句话就能在评论区回答 | 困住你的山，是什么？ |

## 4. 结构和时间模板

顶部进度条的五段就是结构。一小节 3 秒，全片 34 小节，102 秒。

| 小节 | 段落 | 画面 | 屏幕文字 |
|---|---|---|---|
| 0–1 | 症状 | 开场：把悖论演出来 | 悖论两句 |
| 2–6 | 症状 | 六个症状，每屏 2.5 秒 | 每屏：名字 + 两行 |
| 7 | 症状 | 六只小虫合成一只，报出编号和名字 | 这些是同一件事。 |
| 8–12 | 根因 | 进入世界：主角按规则走到「山顶」，镜头拉远，看到更高处 | 两三句，把症状对到世界上 |
| 13–14 | 根因 | 金句一 | 压暗居中 |
| 15–18 | 代价 | 主角尝试改变，失去三样东西，退回；再看一百个人，多数也停在原地 | 四句，其中一句用仿真数字 |
| 19–22 | 补丁 | 规则牌出现、翻面；状态变量开始变（天色变暖） | 出处年份；补丁的人话；补丁的名字 |
| 23–26 | 补丁 | 主角按新规则走到最高处；一百个人重跑，计数、烟花 | 数字对比；交代没成功的 |
| 27–28 | 结论 | 回到主角，他走过的路连起来有了意义 | 两句，把补丁翻译回人生 |
| 29–30 | 结论 | 金句二 | 压暗居中 |
| 31–32 | 结论 | 回到开场的场景：六个症状闪回，主角做出和开场相反的动作，镜头拉远 | 结尾动作一句 |
| 33 | 结论 | 画面继续，停住 | 最后一问，停够 3 秒 |

全片屏幕文字约 20 句。没有字的小节留给画面和音乐。

## 5. 表现手法

下面每一条都是第一期验证过能用的做法，新一期换内容、不换手法。

### 5.1 开场：把悖论演成一个动作

用一个 6 秒的小场景把「因为 A 所以 B」演出来，结尾主角要卡住。第一期：十级台阶，一年一级，走到顶，左右探一下都是「↓ 更差」，头顶冒出「…」。这个场景在片尾还要用一次，设计时就留好「相反动作」的余地。

### 5.2 症状连击

六屏，每屏同一版式：左边一块面板放小动画，右边名字（黄色大字）加两行字，从右推入。左下角每过一屏多一只蓝色小虫。六个小动画必须是同一个形状（第一期：伸出去、缩回来），第二行字等动画「缩回来」的那一下才出现。

### 5.3 命名仪式

六只小虫跳起来合成一只大虫，白闪，落地，打出「BUG-00X」和概念名。这是全片唯一一次正面出现术语。

### 5.4 概念做成关卡

一张连续的地图，主角就是观众。规则写在一块牌子上。进入地图后不再切画面，全靠镜头推近和拉远。常用的三个镜头：贴着主角走；拉远看到全貌（揭示）；扫过其他人。

症状里的东西要搬进世界里当道具（第一期小山顶上的奶茶店、工位、沙发），让观众知道这座山就是刚才那些事。

### 5.5 代价要飘出来

主角每做一次尝试，头顶飘出「某某 −1」，橙色。三次之后退回原地。不解释，观众自己懂。

### 5.6 从一个人到一百个人

先讲主角一个人，再放出一百个小人按同一规则跑，屏幕上出现统计数字。这一步把「你的问题」变成「机制的问题」，也是数字的来源。

### 5.7 补丁是翻牌

规则牌移到画面中央，翻面，换成新规则。同时状态变量开始变化，天色从冷变暖。然后主角按新规则走一遍，再让一百个人重跑：计数器滚动，登顶放烟花，画面轻震。这是全片唯一的高潮。

### 5.8 交代没成功的

重跑后镜头扫过没到顶的人，字幕说明「这不是保证，只是机会」。这一句让前面的数字可信。

### 5.9 金句卡

压暗画面，120 像素大字居中，逐字打出，独占两个小节。全片只有两张：一张诊断（否定自责），一张结论。

### 5.10 回到开场，做相反的动作

片尾回到 5.1 的场景。先快速闪回六个症状（每个 0.2 秒，只留名字），然后主角做出开场没做的那个动作，代价照样飘出来，但这次没有退回。镜头拉远，露出开场镜头里看不到的东西。

### 5.11 最后一问

最后一帧是一个问题，画面继续轻微运动，底部一行小字「人生 bug 图鉴 · 00X 概念名」。问题要让人一句话就能答，而且答案是关于自己的。

### 5.12 贯穿全片的元素

- 顶部五段进度条：症状、根因、代价、补丁、结论。
- 蓝色小虫：系列的标志，出现在症状计数、命名仪式、封面。
- 主角：戴帽子的像素小人，黄色。全景里不小于 20 像素高，会眨眼。

## 6. 文案

### 6.1 通用规则

- 书面语，不用语气词和网络口语。
- 术语只出现补丁的名字和概念名，各一次。
- 一句话一个意思，重点词用颜色标出：问题用蓝色，解法用绿色。
- 数字直接引用仿真变量，不手写。示意数字要一眼能看出是示意。
- 首尾一问一答：结尾动作那句要能回答开头第一句。
- 结尾动作必须由金句二推出。找不到同时「够轻」又「符合逻辑」的具体例子时，不举例，让主角用动作完成。

### 6.2 六个症状

两条要求同时满足：

- **对得上机制。** 逐条核对选题表里的三条成立条件。只是「习惯」或「懒」的例子不要。
- **是一个真实的瞬间。** 写具体场景里发生的一个动作，不写概括。从概念推出来的「标准案例」没有共鸣。

写法：`场景｜做了什么，结果怎样`，结果那半句就是共同动作。

- 奶茶｜新品看了五分钟，还是点了老样子
- 游戏｜新英雄输了两把，换回了本命

配置：学生、工作、生活都要有；从轻到重排，最扎心的放最后；素材优先用自己和身边人真发生过的事。

### 6.3 句式模板

| 位置 | 句式 | 第一期 |
|---|---|---|
| 命名前 | 这些是同一件事。 | 同 |
| 进入世界 | 把三个症状压成一句排比 | 更熟的题。更快的方法。更不费力的关系。 |
| 揭示 | 你在 X。只是 X 不 Y。 | 你站在山顶。只是这座山不高。 |
| 金句一 | 困住你的不是【自责的理由】，是【机制】。 | 困住你的不是懒，是你太会选「更好」。 |
| 代价 | 去【目标】，要先【代价】。 | 去那座山，要先下山。 |
| 认可 | 这很合理。 | 同 |
| 统计 | 一百个小人，【多数】个【困住的状态】。 | 一百个小人，73 个停在小山上。 |
| 出处 | 【年份】年，有人改了这条规则。 | 1983 年 |
| 补丁 | 【新规则的人话】。它叫【名字】。 | 偶尔，允许自己走一步下坡。它叫模拟退火。 |
| 对比 | 同样一百个人：【前】，变成【后】。 | 27，变成 94 |
| 诚实 | 还有【N】个没到。这不是保证，只是机会。 | 6 个 |
| 翻译回人生 | 把状态变量或补丁对到人生的一个阶段或经历 | 年轻，是温度还高的时候。 |
| 金句二 | 只【做 A】的人，【得不到 B】。 | 只肯往上走的人，到不了最高的地方。 |
| 结尾动作 | 回答开头第一句 | 下一步，不必更好。 |

出处年份和人名要查证后再写。

## 7. 视觉规范

- 画布 480×270，放大 4 倍到 1920×1080，最近邻缩放。
- 调色板 Sweetie 16（`src/lib/theme.ts` 的 `P`）。问题、小虫用蓝；解法、亮起的路用绿和黄；代价用橙；失败用红。
- 字体 Fusion Pixel 12px，字号只用 12 的倍数：正文 60，症状名 96，金句 120。
- 辉光：整帧复制一层，模糊后以滤色叠加。亮色像素会发光。
- 天空是五条横向色带，在冷色和暖色之间按状态变量混合。
- 所有随机数带种子，每一帧只依赖帧号。
- 字幕在画面下方居中，带描边，下面垫一条深色渐变。
- 段落之间用像素块转场，段落内部不切。
- 不用 emoji；不用像现成品牌吉祥物的形象；不做「深色底大字加粒子流」的版式。

## 8. 声音

- 音乐由人单独生成和挑选，**先定音乐再排画面**，时间线按音乐的实际拍点对齐。
- 音乐的方向：暖、厚、低频足；从第一秒就有内容；用钢琴或贝斯的八分音符推动，鼓要少；主旋律能哼；情绪是「好奇、探索、下定决心」，不催泪，不滑稽。全曲只在翻牌前抽空一次。
- 写生成提示词时先写情绪和和弦走向，再写乐器，篇幅要短。
- 音效用 `scripts/sfx.ts` 合成，挂在 `sfx.ts` 的时间表上。固定用法：上升的动作逐级升调，下降逐级降调；症状推入一声；命名和金句各一声重音；镜头拉远一声低音；代价一声钝响；翻牌一声；登顶号角加烟花。

## 9. 代码怎么复用

目录：

- `src/lib/`：整个系列通用。画布、文字、字幕、转场、数学工具、调色板。不用改。
- `src/ep01/world.ts`：天空、地形、主角、小虫、烟花、气泡、旗子。主角、小虫、天空、烟花每期通用；地形和道具按新世界重画。
- `src/ep01/script.ts`：时间线、五段进度条、六个症状、全部屏幕文字。新一期主要改这个文件。
- `src/ep01/sim.ts`：仿真。每期重写，导出字幕要用的数字。
- `src/ep01/symptoms.tsx`：症状版式、命名仪式、闪回。版式通用，只换六个小动画和它们的标注字。
- `src/ep01/level.tsx`：开场和关卡。每期重写，镜头关键帧表的写法照搬。
- `src/ep01/ending.tsx`：回到开场和最后一问。结构通用，换动作。
- `src/ep01/Cover.tsx`：封面，横竖两种布局。
- `src/ep01/sfx.ts`、`scripts/sfx.ts`：音效时间表和合成。

起一期新的：

1. 复制 `src/ep01` 为 `src/ep02`，在 `src/Root.tsx` 里注册 `Ep02`、`Ep02Cover`。
2. 按选题表改 `script.ts`：`SYMPTOMS`、`LINES`、`STAGES`、`AT`。
3. 重写 `sim.ts`，用 `scripts/tune.ts` 的方式打印数字、挑一个画面好看的主角种子。
4. 换 `symptoms.tsx` 里的六个小动画（每个按 60 帧设计，约 20 行）。
5. 重写 `level.tsx` 的地图和时间点，再改 `ending.tsx` 的相反动作。
6. 改 `Cover.tsx` 的标题和画面。

命令：

```bash
npm run studio
npx remotion render src/index.ts Ep01 out/ep01.mp4
npx remotion still src/index.ts Ep01Cover out/ep01-cover.png
npx tsx scripts/tune.ts
npx tsx scripts/sfx.ts
```

## 10. 封面、标题、简介

三处分工，不重复：

- **封面给结论。** 一句反常识的话（第一期：困住你的是「更好」）加一个一眼能懂的画面，取自片中的揭示镜头。不放术语，底部小字放系列名和编号，左下角放小虫。
- **标题给问题。** 把悖论改成问句（为什么越会选的人，越容易被困住？）。
- **简介给症状。** 两三个症状开头，一句点出概念和补丁，最后一句和片尾同一个问题。

横屏视频只上传横版封面，所有内容放在中间 810 像素宽的范围内，主页网格只显示这一条。

## 11. 制作顺序

1. 选概念，过第 2 节五关。
2. 填选题表。
3. 写纯文字分镜（按第 4 节的表逐小节写画面和字），确认后再动手。
4. 定音乐。
5. 写仿真，拿到数字，回填文案。
6. 做画面：症状 → 关卡 → 开场和结尾。
7. 加音效，渲染，完整看一遍、听一遍。
8. 出封面、标题、简介。

## 12. 发布前检查

- [ ] 前 6 秒是悖论，没有术语
- [ ] 六个症状都是具体场景，逐条对得上机制的三条成立条件
- [ ] 症状覆盖学生、工作、生活，每屏不少于 2.5 秒
- [ ] 术语只在命名和补丁处各出现一次
- [ ] 数字来自仿真，年份和出处查证过
- [ ] 交代了没成功的那部分
- [ ] 结尾动作能从金句二推出，并且回答了开头第一句
- [ ] 片尾回到了开场的场景
- [ ] 最后一帧是问题，停够 3 秒
- [ ] 没有 emoji，没有口语
- [ ] 封面内容都在中间竖条内；封面、标题、简介不重复

## 附：候选概念

按系列公式初步配对，都还没有过第 2 节的五关，选用前要逐条核对。

| 概念 | 困境 | 世界 | 补丁 |
|---|---|---|---|
| 过拟合 | 被一次经历伤过，从此用它解释所有人 | 小人只记住见过的几条路，换张地图就撞墙 | 正则化：别把每个细节都当规律 |
| 死锁 | 冷战，都在等对方先开口 | 两个小人各握一把钥匙，等对方的那把 | 超时放手：有一方先松开 |
| 贪心算法 | 每次都选眼前最划算的，总账却亏了 | 小人每个路口挑最近的金币，走进死胡同 | 向前多看几步 |
| 最优停止 | 总觉得下一个更好，或者太早定下来 | 小人依次经过一排门，过了不能回头 | 先看前 37%，之后遇到更好的就停 |
| 技术债 | 「先这样，以后再说」越积越多 | 小人每次用胶带补桥，桥越来越晃 | 定期还债 |
