# 《人生 bug 图鉴》制作方法论

第一期（局部最优 × 舒适区）做完后整理。发布时播放量为 0，所以下面的规则来自制作过程中的反复修改和取舍，**还没有被数据验证过**。第一期的数据出来后，应回来修订「开头」「症状」「时长」三节。

第一期遗留、下一期开工前要处理的事：

- BGM 没有定稿，成片目前只有合成音效。
- 音效是代码合成的，没有人试听过音色和音量。
- 横屏在手机竖屏里只占三分之一高度，主角偏小；是否改竖屏没有决定。

## 一、系列设定

一句话：用一个计算机或数学概念，解释一种人人都有的生活困境。

- 每期一个概念，编号进图鉴（BUG-001 局部最优）。
- 概念是答案，不是卖点。封面、标题、开头都不出现术语，术语只在中段揭晓时出现一次。
- 无人声，纯屏幕文字加音乐。情绪交给音乐，信息交给画面和字。
- 画面是全像素游戏风。不用 emoji，不用任何像现成品牌吉祥物的形象，不照搬参考片的版式（深色底大字加粒子）。

## 二、一期的结构

顶部进度条就是结构，五段：

| 段落 | 作用 | 第一期的做法 |
|---|---|---|
| 症状 | 让观众认出自己 | 开头悖论 + 六个日常场景 |
| 根因 | 揭晓概念 | 六只小虫合成一只，报出名字；主角爬上小山 |
| 代价 | 解释为什么走不出来 | 下山三步，每步都变差，退回山顶 |
| 补丁 | 给出解法 | 规则牌翻面；一百个小人重跑，27 变 94 |
| 结论 | 回到观众自己 | 回到开头的场景，做出相反的动作，留一个问题 |

写分镜之前先回答三个问题，答不出来就不要开工：

1. 悖论是什么？（「每一步都选了更好的，所以被困住了」）
2. 金句是什么？（「只肯往上走的人，到不了最高的地方」）
3. 最后留给观众的问题是什么？（「困住你的山，是什么？」）

## 三、文案

- 开头用悖论，不用提问也不用结论。前 6 秒只放两句话，第二句推翻第一句。
- 开头和结尾是一问一答。开头「这十年，你每一步都选了更好的」，结尾「下一步，不必更好」。
- 结尾的动作必须能从金句直接推出来。金句说「要肯下坡」，动作就只能是「接受一次变差」。改简历、换条路回家都被否掉，原因相同：它们不是下坡。
- 找不到合适的具体动作时，不举例，让画面完成动作。具体例子要么太重像说教，要么只对一部分人成立。
- 最后一问要容易回答。「你的山顶是什么」要先想清楚目标，很难答；「困住你的山是什么」只要说出舍不得的东西。
- 不用口语和语气词，不堆术语。
- 全片屏幕文字控制在 20 句左右，留出没有字的小节给画面和音乐。
- 片中出现的数字直接取自仿真变量（27、73、94），不手写。示意性的数字（「第 147 次」）要能一眼看出是示意。

## 四、症状怎么选

这是第一期改得最多的部分，前后换了五轮。结论是两条要求必须同时满足，缺一条都不行。

**逻辑上要成立。** 一个现象算这期概念的案例，要对得上概念的结构。局部最优的结构是三条：现状是自己一步步选出来的，确实不差；往旁边动一下，眼前会先变差；知道有更好的可能。只点三家外卖、歌单三年不换，说的是习惯和懒，对不上，而且和金句「困住你的不是懒」矛盾。

**场景上要是真事。** 从概念往外推出来的例子（「套模板稳拿 45 分」「在这个班是第一」）逻辑标准，但没人觉得那是自己。要写一个具体的瞬间，不写总结。

同时满足两条的办法：留在日常场景里，给每条加上同一个动作。第一期的动作是「试了一下新的，不如原来的，又退回去了」。

- 奶茶｜新品看了五分钟，还是点了老样子
- 游戏｜新英雄输了两把，换回了本命

其他规则：

- 六条里要覆盖学生、工作、生活，观众不只是上班族。
- 从轻到重排，最扎心的放最后。
- 每条两行字，第二行等小动画「退回去」的那一下再出现。
- 六个小动画是同一个形状（伸出去、缩回来），后面主角下山又退回时，观众能自己认出这是同一件事。
- 最可靠的素材来源是作者自己和身边人真实发生过的事，优先于编的。

## 五、画面

规格：480×270 的低分辨率画布放大 4 倍到 1920×1080；Sweetie 16 调色板；Fusion Pixel 12px 字体，字号只用 12 的倍数；所有随机数带种子，画面只依赖帧号。

- 一个主角贯穿全片。全景里至少 20 像素高，会眨眼，关键时刻有动作。
- 中段是一张连续的地图，只靠镜头推拉，不切画面。像素块转场只用在段落之间。
- 天色跟着情绪走：前半段冷，解法出现后变暖。
- 前面出现过的画面，后面要用上。开头的台阶在结尾回来；症状在结尾闪回；下山退回的动作在结尾变成真的走下去。同一个镜头，不同的结果，观众不用解释就能看懂。
- 仿真是真跑出来的。小人的路径、登顶人数都来自 `sim.ts`，这是和「画个示意图」的区别。
- 字幕下面垫一条深色渐变，金句压暗画面后居中放大。

## 六、节奏

- 症状每屏不少于 2.5 秒。1 秒一屏的版本被反馈「没看清就切走了」。
- 金句独占两个小节，前后不放别的字。
- 高潮只有一个（一百人重跑登顶），其余地方不抢。
- 第一期实际时长 102 秒。更短是否更好，等数据。
- 画面的时间点先按固定小节排（目前一小节 3 秒）。音乐定稿后，要按实际拍点把镜头拉远、翻牌、登顶重新对齐，所以音乐越早定越省事。

## 七、音乐

第一期在这里走的弯路最多，六版提示词都没有定稿。

对参考爆款音轨的实测结论（频谱分析，不是听感）：

- 约 112 BPM，第 0 秒就是满音量，没有安静的前奏。
- 能量集中在低频，频谱重心约 200 Hz，整体暗、暖、厚。
- 「进入」靠 80 Hz 以下的超低频抬起来，不靠加鼓。
- 中频有长音一直铺着；律动是匀速的八分音符。
- 大调。全曲只有一次抽空再回来，主段约 30 秒一循环。

写提示词的教训：

- 先写情绪和和弦，再写配器。只写乐器、频段、场景，出来的是没毛病也没感觉的背景音。
- 提示词要短。要求列得越多，模型越平均。
- 不要一次加很多乐器，会变成史诗预告片，主旋律被盖住。
- 情绪要和片子的气质一致。这个系列是冷静观察加一点自嘲，不是催泪，也不是纯街机。
- 节奏不能只靠鼓推，用钢琴或贝斯的持续音型。

挑曲只看一条：主旋律第二次出现时，会不会想跟着哼。配器薄、空间不够、时长不够都能后期补（展宽、混响、按小节循环、滤波做空段、整体升调），旋律没感觉补不了。

下一期的做法：先定音乐，再排画面。

## 八、封面、标题、简介

- 封面给结论，标题给问题，简介给症状，三处不重复。
- 封面不放术语，放一句反常识的话加一个一眼能懂的画面（小山顶上的人，身后一座高得多的山）。术语只出现在底部的系列名里。
- 横屏视频只传横版封面。抖音主页网格只显示中间约 810 像素宽的竖条，所有内容都要落在这个范围里。给横屏视频传竖版封面会被放大裁切。（裁切范围是从一张截图反推的。）
- 简介最后一句和片尾是同一个问题，把评论引到一个话题上。

## 九、工作流程

顺序：

1. 定概念，回答第二节的三个问题。
2. 写纯文字分镜稿，确认后再动画面。第一期有几轮返工是因为跳过了这一步。
3. 选症状，按第四节的两条要求过一遍。
4. 定音乐。
5. 写仿真，拿到真实数字。
6. 做画面，按音乐拍点排时间线。
7. 出封面、标题、简介。

常用命令：

```bash
npm run studio
npx remotion render src/index.ts Ep01 out/ep01.mp4
npx remotion still src/index.ts Ep01Cover out/ep01-cover.png
npx tsx scripts/tune.ts
npx tsx scripts/sfx.ts
```

文件分工（`src/ep01/`）：`script.ts` 是时间线和全部屏幕文字；`sim.ts` 是仿真；`world.ts` 是天空、地形、角色的画法；`symptoms.tsx`、`level.tsx`、`ending.tsx` 是各段画面；`sfx.ts` 是音效时间表；`Cover.tsx` 是封面。做下一期时，`src/lib/` 和 `world.ts` 里的角色、天空可以直接复用。
